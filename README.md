# DrumFeedback

드럼 치는 소리를 마이크로 듣고 지금 몇 BPM인지, 어디서 빨라지고 느려졌는지 알려 주는 웹 도구입니다.

- **설치·설정 없이**: 페이지를 열고 마이크만 허용하면 됩니다. 목표 템포는 비워 둬도 되고, 그러면 처음 4초의 빠르기가 기준이 됩니다.
- **드럼 전용 감지**: 킥·스네어·하이햇 대역별로 타격 순간을 찾아 빠르기를 계산합니다. 30–300 BPM.
- **2배·절반 바로잡기**: 숫자가 두 배나 절반으로 읽히면 ½× · 2× 버튼으로 고칩니다.
- **틀린 숫자 대신 "측정 중"**: 박이 일정하지 않으면 숫자를 보여 주지 않습니다.
- **연습 리포트**: 끝내면 평균·범위·흔들림(%)·안정성 점수와, 기준보다 빨라지거나 느려진 구간을 시각과 함께 보여 줍니다. 3초 넘게 쉬면 다른 연주로 나눕니다.
- **한 화면**: 가운데에 지금 BPM, 그 뒤로 빠르기 선이 아래에서 위로 흘러갑니다. 가운데가 기준이고 오른쪽으로 가면 빠름, 왼쪽으로 가면 느림입니다.
- 소리는 브라우저 안에서만 분석하고 저장하거나 전송하지 않습니다.

## 녹음 파일로 확인하기

화면 아래 **녹음 파일로 확인하기**를 누르고 mp3·m4a·wav 파일을 고르면, 마이크로 들을 때와 같은 방법으로 처음부터 끝까지 분석해
흐름 그래프와 결과를 보여 줍니다. 분석한 뒤 리듬이나 목표 템포를 바꾸면 같은 파일을 다시 분석합니다. 파일도 브라우저 안에서만 처리합니다.

개발할 때는 같은 엔진을 명령줄에서 돌릴 수 있습니다 (ffmpeg 필요).

```bash
npm run analyze -- 녹음.mp3 --feel eighth --every 1   # 1초마다 상태·빠르기·확신·타격 수
```

## 리듬 고르기

화면 아래 **리듬**에서 하이햇·라이드를 어떻게 나눠 치는지 고르면, 목표 템포를 넣지 않아도 어느 간격이 한 박인지 정확히 고릅니다.
싱코페이션한 킥이나 하프타임 때문에 숫자가 2배·절반·3/4배로 나오는 문제를 막습니다. 고른 리듬은 다음에 열 때도 남습니다.

| 리듬 | 이런 곡에 | 자동일 때 |
| --- | --- | --- |
| 8비트 · 하프타임 | 록·팝 8비트, 하프타임, 보사노바, 5/4·7/8 (8분 하이햇) | 하프타임·보사노바는 절반, 5/4·7/8은 ×0.67로 읽을 수 있음 |
| 16비트 · 펑크 | 16분 하이햇, 고스트 노트, 싱코페이션 킥 | ×1.33으로 읽을 수 있음 |
| 셔플 · 스윙 | 셔플, 스윙 재즈 라이드, 하프타임 셔플, 레게 원드롭 | 셔플·스윙은 대체로 맞음 |
| 바운스 (16분 스윙) | 힙합·R&B 바운스, 스윙 16분 | ×2·×0.67로 읽을 수 있음 |
| 셋잇단 · 6/8 · 12/8 | 12/8 블루스, 6/8 (점4분음표를 한 박으로) | 대체로 맞음 |
| 4분음표만 | 메트로놈 연습, 패드 4분음표 | 맞음 |

합성 드럼으로 만든 18가지 리듬을 리듬만 골라서(목표 템포 없이) 모두 1% 안으로 읽습니다. `tests/rhythms.test.ts`가 이를 검사합니다.
목표 템포를 넣으면 그 근처에서만 찾으므로 리듬 설정보다 우선합니다.

## 합주할 때

베이스·기타·건반·보컬이 함께 들어와도 박을 읽습니다. 합성한 합주 소리로 확인한 결과입니다 (`tests/band.test.ts`).

| 다른 악기 음량 (드럼 대비) | 리듬 자동 | 리듬을 고르면 |
| --- | --- | --- |
| 드럼보다 작거나 같음 | 맞음 | 맞음 |
| 드럼보다 2배 (+6dB) | 2배·0.67배로 잘못 읽는 경우가 많음 | 맞음 |
| 드럼보다 4배 (+12dB) | 대체로 틀림 | 맞음 |

베이스가 8분음표로 킥만큼 크게 들어오면 자동은 8분음표를 한 박으로 착각합니다. 합주할 땐 리듬을 골라 두세요. 폰은 드럼 가까이, 앰프에서 멀리 두는 것이 좋습니다.

합성한 드럼 소리로만 검증했고, 실제 드럼·실제 마이크에서의 정확도는 아직 확인하지 않았습니다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # 타격 검출·빠르기 추정·리포트 테스트
npm run build    # 타입 검사 + 배포용 빌드(dist/)
```

마이크는 `localhost`나 HTTPS 주소에서만 쓸 수 있습니다.

## 배포 (GitHub Pages)

`.github/workflows/deploy.yml`이 기본 브랜치에 push될 때마다 테스트 → 빌드 → GitHub Pages 배포를 합니다.
저장소 **Settings → Pages → Source**를 **GitHub Actions**로 한 번 바꿔 줘야 합니다.

## 구조

| 파일 | 역할 |
| --- | --- |
| `src/onset.ts` | 소리에서 타격 순간 찾기 (대역별 에너지 변화) |
| `src/tracker.ts` | 타격 간격에서 빠르기 추정, 2배·절반 고르기 |
| `src/engine.ts` | 소리 → 지금 상태(조용함·측정 중·확정·잠깐 놓침) |
| `src/session.ts` | 연습 기록과 리포트 |
| `src/mic.ts` | 마이크 입력 (AudioWorklet) |
| `src/main.ts` | 화면: 숫자, 그래프, 리포트 |
